# 阿里云百炼（DashScope）大模型接入指南

> 如果你要接的是控制台标题为 **Model Router**、地址为 `model-router.edu-aliyun.com` 的平台，  
> 请改看：[`Model-Router大模型接入指南.md`](./Model-Router大模型接入指南.md)。  
> 本文仅适用于直接调用百炼 `dashscope.aliyuncs.com` 的场景。
>
> 本文整理自已跑通项目（电动车资讯站 `evchetx`、热点摘要 `Horizon` 等）的实际接入经验。  
> 目标：下一个项目可以直接照抄配置与代码，少走弯路。

---

## 1. 结论先看

我们实际用的是 **阿里云百炼 / DashScope**，同一个 API Key（`sk-...`）通常可以同时用于：

| 能力 | 协议 | Base URL | 典型模型 |
|------|------|----------|----------|
| 文本对话 / 结构化输出 | **OpenAI 兼容** | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`、`qwen3.7-flash` 等 |
| 文生图 / 图生图 | **百炼原生多模态** | `https://dashscope.aliyuncs.com/api/v1` | `qwen-image-2.0` 等 |

**最容易踩坑的点：**

1. **文字接口** 和 **生图接口** 的 Base URL **不一样**。  
2. 文字模型（如 `qwen3.7-flash`）**不能**拿来出图；出图必须用 `qwen-image-*`。  
3. Key **只能放服务端环境变量**，绝不能写进前端、Git、聊天记录。  
4. 官网智能体面板当前只预留了 `VITE_AGENT_API_URL` 转发层；真正调百炼应放在 **后端**，前端只调自己的 `/api/...`。

---

## 2. 开通与拿 Key

1. 打开阿里云百炼控制台，创建/复制 API Key（形如 `sk-xxxxxxxx`）。  
2. 确认账户已开通要用的模型（文本、`qwen-image`）。  
3. 本地/服务器 `.env` 写入 Key，**不要提交到 Git**。  
4. 若 Key 曾在聊天、截图、仓库里出现过，**立刻轮换**，旧 Key 作废。

推荐 `.gitignore`：

```gitignore
.env
.env.local
.env.production
*.pem
```

## 3. 环境变量模板（推荐直接复用）

```env
# ========== 文本（OpenAI 兼容） ==========
CONTENT_TEXT_API_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
CONTENT_TEXT_API_KEY=sk-你的密钥
CONTENT_TEXT_MODEL=qwen3.7-flash
CONTENT_TEXT_TIMEOUT_MS=60000

# ========== 生图（百炼原生） ==========
CONTENT_IMAGE_PROVIDER=dashscope
CONTENT_IMAGE_API_BASE_URL=https://dashscope.aliyuncs.com/api/v1
CONTENT_IMAGE_API_PATH=/services/aigc/multimodal-generation/generation
CONTENT_IMAGE_API_KEY=sk-你的密钥
CONTENT_IMAGE_MODEL=qwen-image-2.0
CONTENT_IMAGE_SIZE=1024*1024
CONTENT_IMAGE_TIMEOUT_MS=120000
```

说明：

- 文本、图片可以用 **同一个 Key**。  
- `CONTENT_IMAGE_SIZE` 百炼侧常用 `1024*1024`（星号），不是 OpenAI 的 `1024x1024`。  
- 若误把图片 Base 配成 `compatible-mode/v1`，服务端应改写到 `/api/v1`（见下文代码）。

## 4. 文本调用（OpenAI 兼容 `/chat/completions`）

### 4.1 请求要点

- Method：`POST`
- URL：`{BASE}/chat/completions`
- Header：
  - `Authorization: Bearer {API_KEY}`
  - `Content-Type: application/json`
- Body 与 OpenAI Chat Completions 基本一致

### 4.2 curl 最小示例

```bash
curl https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions \
  -H "Authorization: Bearer $CONTENT_TEXT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.7-flash",
    "temperature": 0.2,
    "messages": [
      {"role": "system", "content": "你是专业助手，用简洁中文回答。"},
      {"role": "user", "content": "用三句话介绍空间智能体。"}
    ]
  }'
```

成功时取：

```text
choices[0].message.content
```

### 4.3 Node.js / TypeScript 可复用封装

```ts
type ChatMessage = { role: 'system' | 'user' | 'assistant'; content: string }

function apiUrl(baseUrl: string, path: string) {
  return `${baseUrl.replace(/\/+$/, '')}/${path.replace(/^\/+/, '')}`
}

export async function chatCompletions(params: {
  messages: ChatMessage[]
  model?: string
  temperature?: number
  jsonObject?: boolean
  timeoutMs?: number
}) {
  const baseUrl = process.env.CONTENT_TEXT_API_BASE_URL
    || 'https://dashscope.aliyuncs.com/compatible-mode/v1'
  const apiKey = process.env.CONTENT_TEXT_API_KEY
  const model = params.model || process.env.CONTENT_TEXT_MODEL
  if (!apiKey) throw new Error('未配置 CONTENT_TEXT_API_KEY')
  if (!model) throw new Error('未配置 CONTENT_TEXT_MODEL')

  const response = await fetch(apiUrl(baseUrl, '/chat/completions'), {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${apiKey}`,
      'Content-Type': 'application/json',
    },
    signal: AbortSignal.timeout(params.timeoutMs || Number(process.env.CONTENT_TEXT_TIMEOUT_MS || 60000)),
    body: JSON.stringify({
      model,
      temperature: params.temperature ?? 0.2,
      ...(params.jsonObject ? { response_format: { type: 'json_object' } } : {}),
      messages: params.messages,
    }),
  })

  if (!response.ok) {
    const detail = (await response.text()).slice(0, 500)
    throw new Error(`文字 API HTTP ${response.status}: ${detail}`)
  }

  const payload = await response.json() as any
  const content = payload?.choices?.[0]?.message?.content
  if (typeof content !== 'string' || !content.trim()) {
    throw new Error('文字模型未返回有效 content')
  }
  return { content, raw: payload }
}
```

### 4.4 需要模型返回 JSON 时

1. 请求加：`response_format: { type: "json_object" }`  
2. system / user 提示里明确「只输出 JSON」  
3. 解析前先去掉可能的 ```json 代码围栏：

```ts
function parseJsonText(value: string) {
  const cleaned = value.trim()
    .replace(/^```(?:json)?\s*/i, '')
    .replace(/\s*```$/, '')
  return JSON.parse(cleaned)
}
```

## 5. 生图调用（百炼原生多模态）

### 5.1 为什么不能用 compatible-mode？

`compatible-mode/v1` 主要兼容 Chat Completions。  
`qwen-image` 走百炼原生：

```text
POST https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation
```

### 5.2 文生图请求体

```json
{
  "model": "qwen-image-2.0",
  "input": {
    "messages": [
      {
        "role": "user",
        "content": [
          { "text": "新闻配图，新能源汽车，真实摄影风格，无文字无水印" }
        ]
      }
    ]
  },
  "parameters": {
    "size": "1024*1024",
    "n": 1,
    "watermark": false,
    "prompt_extend": true
  }
}
```

图生图时，`content` 先放图片再放文本：

```json
"content": [
  { "image": "https://example.com/source.jpg" },
  { "text": "保持主体，改成更明亮的展厅灯光" }
]
```

### 5.3 响应解析（注意字段路径）

百炼常见返回：

```text
output.choices[0].message.content[].image
```

也可能出现 `url` / `imageUrl`。OpenAI 风格则是 `data[0].url` 或 `data[0].b64_json`。

推荐统一解析：

```ts
function parseImageResponse(payload: any): { url?: string; buffer?: Buffer } {
  const messageContent = payload?.output?.choices?.[0]?.message?.content
  const dashscopeItem = Array.isArray(messageContent)
    ? messageContent.find((item: any) => item?.image || item?.url || item?.imageUrl)
    : undefined
  const item = payload?.data?.[0]
    || payload?.images?.[0]
    || payload?.output?.results?.[0]
    || dashscopeItem
    || payload

  const remoteUrl = item?.url || item?.image || item?.imageUrl || item?.output_url
  const base64 = item?.b64_json || item?.base64
  return {
    url: typeof remoteUrl === 'string' ? remoteUrl : undefined,
    buffer: typeof base64 === 'string' ? Buffer.from(base64, 'base64') : undefined,
  }
}
```

### 5.4 Base URL 纠错（强烈建议保留）

如果有人把图片 Base 误配成 `compatible-mode`，自动纠正到 `/api/v1`：

```ts
function dashscopeImageApiUrl(baseUrl: string, endpoint: string) {
  const url = new URL(baseUrl)
  if (/\/compatible-mode(?:\/v1)?\/?$/i.test(url.pathname)) {
    url.pathname = '/api/v1'
  }
  return `${url.toString().replace(/\/+$/, '')}/${endpoint.replace(/^\/+/, '')}`
}
```

### 5.5 模型名校验

若配置了非图片模型却去调生图，常见现象是「HTTP 成功但不返回图片」。应显式提示：

```ts
if (!/^qwen-image/i.test(model)) {
  throw new Error(`模型 ${model} 未返回图片，请将 CONTENT_IMAGE_MODEL 配为 qwen-image-2.0`)
}
```

## 6. 架构建议（新项目怎么接）

```text
浏览器 / App
    │
    ▼
你的后端 API（鉴权、限流、审计、隐藏 Key）
    │
    ├─ 文本  → DashScope compatible-mode /chat/completions
    └─ 生图  → DashScope /api/v1/.../generation
```

### 不要做的事

- 前端直接带 `sk-` 调百炼（Key 会泄露）  
- 把 Key 写进 Vite 的 `VITE_*` 变量（会打进前端包）  
- 用文本模型名去调生图  
- 文本、生图共用同一个错误的 Base URL

### 可以做的事

- 后端统一封装 `chatCompletions` / `generateImage`  
- 按业务设置 timeout、重试、熔断  
- 生图结果转存到 COS/OSS，不长期依赖临时外链  
- 需要 JSON 时强制 `response_format` + 服务端校验字段

## 7. 与本官网智能体面板的关系

本仓库前端对话入口：

- UI：`src/components/agent-chat.js`
- API 适配：`src/services/agent-chat-api.js`

当前约定：

```env
# 前端只配「你自己的后端地址」，不要配百炼地址
VITE_AGENT_API_URL=https://your-api.example.com/api/agent/chat
```

前端会 POST：

```json
{
  "sessionId": "sess_xxx",
  "agentId": "spatial-advisor",
  "message": "用户输入",
  "history": [{ "role": "user", "content": "..." }],
  "page": "home",
  "timestamp": 1234567890
}
```

期望后端返回：

```json
{ "reply": "回复文本", "meta": {} }
```

后端内部再调用百炼文本接口（第 4 节），把 `choices[0].message.content` 映射成 `reply`。

未配置 `VITE_AGENT_API_URL` 时，前端走本地 mock，不访问大模型。

## 8. 联调检查清单

### 文本

- [ ] `.env` 已加载（PM2 / systemd / Windows 服务要 `--update-env` 或重启进程）  
- [ ] Base 是 `.../compatible-mode/v1`（末尾不要多拼一层 `/v1`）  
- [ ] Header 是 `Bearer sk-...`  
- [ ] 模型名控制台里确实可用  
- [ ] 能读到 `choices[0].message.content`

### 生图

- [ ] Base 是 `.../api/v1`（不是 compatible-mode）  
- [ ] Path 是 `/services/aigc/multimodal-generation/generation`  
- [ ] 模型是 `qwen-image-*`  
- [ ] size 用 `1024*1024`  
- [ ] 能解析到 `output.choices[0].message.content[].image`

### 常见报错对照

| 现象 | 原因 | 处理 |
|------|------|------|
| 401 / Invalid | Key 错、过期、未开通 | 换新 Key，检查控制台 |
| 404 / 路径错 | Base/Path 拼错 | 对照第 3、5 节 |
| 200 但无图片 | 用了文本模型或解析字段错 | 换 `qwen-image-*`，按第 5.3 解析 |
| 前端能调通、线上不行 | 生产环境变量未注入 | 重启进程并确认 env |
| CORS 错误 | 浏览器直连百炼 | 改为服务端转发 |

## 9. 最小后端转发示例（Express）

适合官网、落地页、内部工具快速接入：

```js
import express from 'express'

const app = express()
app.use(express.json({ limit: '1mb' }))

app.post('/api/agent/chat', async (req, res) => {
  try {
    const { message, history = [] } = req.body || {}
    if (!message || typeof message !== 'string') {
      return res.status(400).json({ error: 'message required' })
    }

    const base = process.env.CONTENT_TEXT_API_BASE_URL
      || 'https://dashscope.aliyuncs.com/compatible-mode/v1'
    const key = process.env.CONTENT_TEXT_API_KEY
    const model = process.env.CONTENT_TEXT_MODEL || 'qwen3.7-flash'
    if (!key) return res.status(500).json({ error: 'TEXT API KEY missing' })

    const messages = [
      { role: 'system', content: '你是安托未来空间智能顾问，回答简洁专业。' },
      ...history.slice(-12).map((m) => ({ role: m.role, content: m.content })),
      { role: 'user', content: message },
    ]

    const upstream = await fetch(`${base.replace(/\/$/, '')}/chat/completions`, {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${key}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({ model, temperature: 0.3, messages }),
    })

    if (!upstream.ok) {
      const detail = await upstream.text()
      return res.status(502).json({ error: `upstream ${upstream.status}`, detail: detail.slice(0, 300) })
    }

    const data = await upstream.json()
    const reply = data?.choices?.[0]?.message?.content || '暂时无法回答，请稍后再试。'
    res.json({ reply, meta: { model, provider: 'dashscope-compatible' } })
  } catch (error) {
    res.status(500).json({ error: error instanceof Error ? error.message : String(error) })
  }
})

app.listen(3000)
```

前端：

```env
VITE_AGENT_API_URL=http://localhost:3000/api/agent/chat
```

## 11. 安全提醒（必读）

1. API Key 只放服务器环境变量。  
2. 日志里不要打印完整 Key；出错只保留前 4 位。  
3. 生产建议加：登录鉴权、IP/频率限制、按用户/租户计量。  
4. 若 Key 曾泄露到聊天或仓库，立即在百炼控制台禁用并重建。
