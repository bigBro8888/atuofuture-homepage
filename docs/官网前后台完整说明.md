# 安托未来官网：前后台、产品内容与结构说明

换电脑后先看这份文档。目标：能本地跑起来、知道每页内容从哪来、知道后台改什么、知道线上怎么更新。

---

## 1. 这是什么

公司官网（安托未来 / Atuo Future）：介绍空间智能体、行业方案、智能硬件、新闻、AI Token，以及 App 下载。

技术形态：

- 前台：多页静态站点（Vite 打包），不是 React/Vue 单页应用。
- 后台：`/admin/` 运营后台，登录后改文案、图、App 下载配置。
- API：Express，默认本机 `8787`。后台保存写入 **`server/data/store.json`**（不进 Git）。

仓库：

- GitHub：https://github.com/bigBro8888/atuofuture-homepage
- 远程名：`github`，分支：`main`
- 本地常见路径：公司首页项目目录下的 `首页1`

**Push 代码 ≠ 上线后台内容。** Git 只带代码和默认图。后台改过的文案/外链图只存在那台机器的 `store.json`。换电脑或换服务器，要重新在对应后台发布一次。

## 2. 新电脑怎么跑

环境：Node.js **≥ 20**，Git。

```bash
git clone https://github.com/bigBro8888/atuofuture-homepage.git
cd atuofuture-homepage
npm install
copy .env.example .env
```

`.env` 至少改：`JWT_SECRET`、`ADMIN_PASSWORD`。不要把 `.env` 提交到 Git。

两个终端：

```bash
npm run dev        # 前台 Vite：http://127.0.0.1:5188
npm run dev:api    # API：http://127.0.0.1:8787
```

Vite 已把 `/api` 代理到 `8787`。只开前台、不开 API 时，后台登录和 CMS 会失败，前台会回落到代码里的默认文案。

- 前台：http://127.0.0.1:5188/
- 后台：http://127.0.0.1:5188/admin/
- 默认账号：`.env` 里的 `ADMIN_EMAIL`（示例 `admin@atuofuture.com`）

构建：

```bash
npm run build      # 输出 dist/
npm test           # server/test
```

Windows 推 GitHub 若遇代理/证书问题，单次命令指定代理和证书，不要改全局 git config。作者可用临时环境变量 `bigBro8888 <bigBro8888@users.noreply.github.com>`。

## 3. 目录怎么读

| 路径 | 作用 |
|------|------|
| `index.html` 等各页 HTML | 前台页面壳 |
| `src/scripts/` | 各页 JS（首页 `home-siemens.js`、后台 `admin-apps.js`） |
| `src/styles/main.css` | 前台主样式（西门子式首页也在这里） |
| `src/data/` | **写死在代码里的产品内容**（方案、智能体、硬件、新闻、导航） |
| `src/components/` | 顶栏、页脚、下载弹层、对话组件 |
| `src/services/` | 调公开 CMS / App 接口 |
| `admin/index.html` | 后台壳 |
| `server/src/` | API |
| `server/data/store.json` | 运行时数据（gitignore） |
| `server/uploads/` | 后台上传图（gitignore） |
| `public/images/` | 站内图片，会打进 `dist` |
| `docs/` | 说明文档（含本文件） |
| `app download/` | 设计稿，**不要提交、不要当线上代码** |

Vite 入口见 `vite.config.js` 的 `build.rollupOptions.input`。开发端口绑 `127.0.0.1:5188`，不要用 `localhost` 乱切 IPv6。

## 4. 前台页面地图

路径都是带尾斜杠的静态目录（`xxx/index.html`）。

| 路径 | 页面 | 主要内容从哪来 |
|------|------|----------------|
| `/` | 首页 | HTML 骨架 + CMS `home`（发布后覆盖）+ 默认图 |
| `/solutions/` | 行业方案列表/详情 | `src/data/solutions.js`；首屏标题/Banner 可被 CMS simple `solutions` 覆盖 |
| `/agents/` | 空间智能体总览 | `src/data/agents-overview.js` 等；首屏可被 CMS `agents` 覆盖 |
| `/agent-detail/?id=` | 单个智能体 | `src/data/agents-detail.js`、`product-agents.js` |
| `/hardware/` | 硬件矩阵 | `src/data/hardware-catalog.js`；首屏 CMS `hardware` |
| `/hardware/product/?id=` | 硬件详情 | `src/data/hardware-product-details.js` |
| `/news/` | 新闻列表 | `src/data/news.js`；页头 CMS `news` |
| `/news-detail/?id=` | 新闻详情 | `src/data/news.js` |
| `/about/` | 关于我们 | CMS `about`（发布后）+ `about/index.html` |
| `/ai-token/` | AI Token 介绍/购买入口 | `ai-token-store.js`；首屏 CMS `ai-token` |
| `/app-download/` | App 下载 | `/api/public/apps/artink` |
| `/order/` | 下单相关页 | `order.js` |
| `/admin/` | 运营后台 | `/api/admin/*`，需登录 Cookie |

顶栏/mega menu：`src/data/site-nav.js`。联系方式默认：`src/data/contact.js`，发布「全站设置」后会被 CMS 覆盖。Token 外链：`src/data/site-links.js`。

全站脚本入口：`src/scripts/main.js`（导航、页脚、下载弹层、按页面 init）。

## 5. 产品内容结构（业务侧）

公司定位：以 **AI 智能体** 为大脑、**智能硬件** 为感知/执行，给楼宇、园区、酒店等做可交付的空间智能。

### 5.1 八个空间智能体（全站同一套 id）

| id | 名称 | 典型任务 |
|----|------|----------|
| `space` | 空间服务智能体 | 灯光空调、工单、信息发布 |
| `energy` | 能源能耗智能体 | 分项计量、有无人节能 |
| `meeting` | 会议智能体 | 预约、签到、中控、音视频 |
| `exhibition` | 展厅智能体 | 大屏、孪生、讲解 |
| `visitor` | 访客接待智能体 | 邀约、通行、接待 |
| `opc` | 商业空间运营智能体 | 招商带看、签约（OPC） |
| `hospitality` | 酒店公寓智能体 | 分房、门锁、客房、费用 |
| `asset` | 资产管理智能体 | 盘点、领用借还 |

详情页：`/agent-detail/?id=space` 这种。首页轮播长图默认：`public/images/home-agents/{id}.jpg`（建议 21:9）。

代码源：`src/data/product-agents.js`、`agents-detail.js`、`agents-overview.js`。首页 CMS 的 `agents.items[]` 字段：`id, name, sceneTitle, sceneCaption, imageUrl`。

### 5.2 行业解决方案

`src/data/solutions.js`，id：

- `campus` 智慧园区
- `building` 智慧楼宇
- `school` 智慧学校
- `hotel` 智慧酒店
- `apartment` 智慧公寓
- `commercial` 商业资产

前台：`/solutions/?id=building`。每条含痛点、能力、关联智能体/硬件等。后台目前只编该页**首屏**（标题、副标题、Banner），不编每条方案正文。

### 5.3 智能硬件三条产品线

导航：`hardware/?line=space|retail|consumer`

- 空间智能：中控、传感、网关、会议办公
- 新零售与行业电子纸：价签、低温标签、盘点
- 3C 数码：墨水屏配件等

目录在 `hardware-catalog.js`，SKU 详情在 `hardware-product-details.js`。后台同样主要覆盖硬件页首屏。

### 5.4 首页区块（西门子式）

`index.html` 从上到下：

1. 首屏多屏轮播（最多 12 屏，CMS `heroSlides`）
2. 中部推广条（CMS `banner`）
3. 空间智能体一览（8 个可逐个编图和场景文案）
4. 产品与方案横滑
5. 新闻三列
6. 探索安托未来宫格

后台首页编辑器左侧大纲与这 6 块一一对应，点一项只编一块。

### 5.5 App 下载

公开接口：`GET /api/public/apps/artink`。后台「App 下载页」改名称、Banner、商店链接、能力卡片；Android 包走 OSS 版本发布。下载统计在后台「下载统计」。

## 6. 后台信息架构

打开 `/admin/`，侧栏大致：

1. **全站设置** `#site`：Logo、中英文品牌名、顶栏「下载 App / 预约演示」、Token 入口、邮箱电话地址、页脚。发布后全站顶栏页脚生效。
2. **页面目录** `#overview`：对照前台路径的入口列表（`src/data/admin-sitemap.js`）。
3. **网站内容**
   - 官网首页 `#home`：按区块草稿 → 发布
   - 关于我们 `#about`
   - 行业方案 `#page-solutions`（simple）
   - 空间智能体 `#page-agents`（simple，只编总览首屏，不是 8 个详情页正文）
   - 智能硬件 `#page-hardware`
   - 新闻中心 `#page-news`
   - AI Token `#page-ai-token`
   - App 下载页 `#config`
4. **App 分发**：版本发布、回滚、统计
5. **系统**：账号权限、操作审计（超级管理员）

角色权限（`server/src/modules/admin/auth.js`）：

- `super_admin`：配置、发版、统计、账号、审计
- `editor`：写配置、看统计
- `publisher`：发版、看统计
- `analyst`：只看统计

登录 Cookie 名：`atuo_admin_session`，JWT 8 小时。  
**HTTP 访问必须 `COOKIE_SECURE=false`。** 只有全站 HTTPS 才设 `COOKIE_SECURE=true`，否则浏览器不存 Cookie，后台会出现 `authentication_required`，表单空白。

工作流：改草稿 → 保存草稿（线上不变）→ 发布（前台公开接口才读到）。未发布时前台用代码默认值。

## 7. 两层内容：代码默认 vs CMS

```
前台页面
  ├─ 结构/交互：HTML + JS（仓库里）
  ├─ 产品长文案、方案/硬件/新闻正文：src/data/*.js（仓库里，改代码才变）
  └─ 运营可改的标题/Banner/首页区块/Logo：store.json（每台机器一份）
```

公开 CMS 接口（无登录）：

- `GET /api/public/pages/home`
- `GET /api/public/pages/about`
- `GET /api/public/pages/site`
- `GET /api/public/pages/simple/:key`（key = solutions | agents | hardware | news | ai-token）

后台对应：`/api/admin/pages/...` 的 GET / draft PUT / publish POST，需登录。

图片：可上传到 `server/uploads`（经 `/api/public/uploads`），或填站内路径如 `/images/home-agents/space.jpg`，或 https 外链。外链只存在 store，不进 Git。

## 9. 线上部署（当前这台阿里云）

机器：`47.103.102.65`（华东 2 上海）。同机还有很多其它站，**不要再占用 80/443**。

| 项 | 值 |
|----|----|
| 代码目录 | `/var/www/mydoc/atuofuture` |
| 静态站 | systemd `atuofuture-nginx`，配置 `/etc/nginx/atuofuture-only.conf` |
| 对外端口 | **18180**（安全组放行 TCP 18180，来源 `0.0.0.0/0`） |
| API | systemd `atuofuture-home`，只听 `127.0.0.1:18087`，nginx 把 `/api/` 反代过去 |
| 进程用户 | `atuoapp` |
| 环境变量 | `/var/www/mydoc/atuofuture/.env`（含 `COOKIE_SECURE=false`） |

访问：

- 官网：http://47.103.102.65:18180/
- 后台：http://47.103.102.65:18180/admin/

更新代码（在服务器上，目录属主是 atuoapp）：

```bash
cd /var/www/mydoc/atuofuture
sudo -u atuoapp git pull
sudo -u atuoapp npm run build
sudo systemctl restart atuofuture-home
# 只改了 dist 静态文件一般不用重启 nginx；改了 nginx 配置才 reload/restart atuofuture-nginx
```

以后改代码上线后，**普通按 F5 即可**看到新页面，不必 Ctrl+F5。HTML 已设 `Cache-Control: no-cache`，带哈希的 `/assets/` 会长缓存；Ctrl+F5 会强制重下全部图片和脚本，所以会很慢，期间也会一直停在旧画面。

系统自带 `nginx.service` 因 443 被其它 Node 占用已失败多日。本站用独立 nginx，只听 18180，避免抢走其它站点的 80。

测试站（另一套）：`/var/www/mydoc/test-atuofuturehome`，端口曾用 18788，不要和本仓库搞混。

## 10. 换电脑后清单

1. 克隆仓库，`npm install`，复制 `.env.example` → `.env`。
2. `npm run dev` + `npm run dev:api`，本机 5188 看前台，5188/admin 看后台。
3. 改产品长文案：改 `src/data/` 再提交。
4. 改首页区块/Logo/各页首屏：进后台保存并**发布**。本地发布只影响本机 `server/data/store.json`。
5. 要上线：push `main`，服务器 pull + build + 必要时重启 API；**再登线上后台把内容发布一遍**（如果线上 store 是空的）。
6. 不要提交：`.env`、密钥、`server/data/`、`server/uploads/`、`app download/`、`tmp-screenshots/`。
7. HTTP 后台登录失败：查 `COOKIE_SECURE`，必须为 false。
